# Lessons learned

| Date | Ce qui s'est mal passé | Règle à suivre |
|------|------------------------|----------------|
| 2026-04-21 | Prompt rendu avec fences \`\`\` imbriquées — le bloc externe terminait sur le premier \`\`\`bash interne, cassant l'affichage | Pour un prompt/doc à copier-coller contenant des exemples code, ne JAMAIS wrapper le tout dans un code fence externe. Utiliser du markdown plat avec blocs \`\`\`lang inline. |
| 2026-04-21 | Tâche Claude.ai cloud lancée sans setup initial → agent démarré dans /home/user vide (repo pas cloné automatiquement par le GitHub connector) | Toujours inclure en première section du prompt cloud : \`cd /home/user && git clone https://github.com/{owner}/{repo}.git && cd {repo}\`. Aussi configurer les secrets (GOOGLE_PLACES_API_KEY etc.) dans la config Claude.ai — le .env.local n'est pas dans le repo. |
| 2026-04-21 | Daily run Bilbao/Montpellier : apostrophes non-échappées dans une string single-quoted en TypeScript — \`'Puppy'\` dans \`'...'\` a cassé le build Vercel. Bizarrement la version EN/ES utilisait bien \`\\'Puppy\\'\` mais pas FR. | Dans les strings single-quoted de cityContent.ts, TOUTES les apostrophes/guillemets simples à l'intérieur doivent être échappés \`\\'\`. Alternative plus safe : utiliser des backticks \`\`\`...\`\`\` pour les strings contenant des citations. Ajouter \`npx tsc --noEmit\` dans Step 11 du pipeline AVANT le commit — l'audit ne détecte pas les erreurs TS. |
| 2026-04-21 | Même run : \`export default cityContent\` SUPPRIMÉ accidentellement quand l'agent a ajouté Bilbao/Montpellier en fin de fichier. Build Vercel crash "Export default doesn't exist". Mon \`npx tsc --noEmit\` sur UN seul fichier ne détectait pas ça (le fichier seul compile OK, c'est l'import depuis page.tsx qui échoue). | Ne JAMAIS éditer lib/cityContent.ts en insérant juste avant \`}\` final sans vérifier que \`export default cityContent\` est toujours en dessous. Step 11 du pipeline doit inclure \`npm run build\` COMPLET (pas juste tsc --noEmit sur un fichier), qui détecte les imports cassés. Alternative plus rapide : \`grep -c "^export default cityContent" lib/cityContent.ts\` doit retourner 1. |
| 2026-04-21 | Villes dans lib/cityContent.ts ajoutées par la tâche nocturne TOUJOURS en fin de fichier (Bilbao + Montpellier après Athens), désordre total (paris, barcelona, rome... puis chaos) | Les nouvelles villes doivent être insérées alphabétiquement. Règle dans Step 8 : trouver le slug qui vient APRÈS alphabétiquement et insérer JUSTE AVANT lui. Le fichier a été trié via scripts /tmp/sort-citycontent.py. Si ça repart dans le désordre, re-trier. |
| 2026-04-21 | Noms de sights avec descripteurs anglais collés : "Écusson Medieval Quarter", "Parc Méric Off-Leash Area", "Berges du Lez Riverside Walk" — le champ \`name\` n'est pas localisé, donc "Medieval Quarter" apparaît tel quel sur la page française. 11 noms cassés au total (Montpellier, Riga, Warsaw, Salzburg, Munich, Oslo, Tallinn, Bilbao). | (1) Le champ \`name\` des sights doit être un NOM PROPRE pur (locution dans la langue du pays ou neutre), jamais un descripteur anglais collé. (2) Si on veut ajouter une traduction, utiliser des parenthèses : "Stari Grad (Old Town Walls)" OK. (3) check-i18n.mjs a été étendu pour détecter automatiquement les descripteurs interdits (Off-Leash Area, Riverside Walk, Sculpture Park, Medieval Quarter, River Path, etc.) — tourne à chaque \`npm run build\` donc bloque le déploiement si présent. |
| 2026-04-21 | Link "← Destinations" sur page destination visible mais NON CLIQUABLE — l'image de fond du hero (\`<Image fill>\` dans un \`div.absolute.inset-0\`) couvre tout le hero et capture les clics. Le div de contenu n'avait pas de \`relative z-10\` donc restait sous l'image en stacking. | Règle pour tout hero avec image de fond \`absolute\` : (1) le div overlay image doit avoir \`pointer-events-none\`, (2) le div de contenu doit avoir \`relative z-10\` pour passer au-dessus. Vérifier systématiquement sur toute nouvelle page avec hero image que les liens/boutons sont réellement cliquables. |
| 2026-04-21 | Hôtels ajoutés par la tâche nocturne (et par les commits manuels) n'étaient étiquetés que \`dog-friendly\` et jamais \`cat-friendly\`, même quand la politique Booking dit "Pets are allowed" (ce qui inclut les chats). Résultat : les 9 villes récentes (Marseille, Rotterdam, Bologna, Cologne, San Sebastián, Toulouse, London, Bilbao, Montpellier) avaient 0 à 3 hôtels cat-friendly sur 5-6. | Règle Step 9 : si la politique de l'hôtel dit "Pets are allowed" (ou "dogs and cats", ou "animaux"), ajouter AUSSI \`cat-friendly\` dans \`categories\`. N'ajouter \`dog-friendly\` seul QUE si la politique exclut explicitement les chats ("only dogs", "dogs only"). La plupart des hôtels Booking pet-friendly acceptent les 2. |
| 2026-04-21 | L'agent nocturne a ajouté Bilbao + Montpellier À LA FIN de TOUS les fichiers concernés : destinations.json (ordre 50/51), editorial.ts (3 blocs en/fr/es), hotels.json. Résultat visible : pages catégories (dog-friendly, cat-friendly) affichent Bilbao et Montpellier hors ordre alpha. CityContent.ts avait déjà été re-trié, mais les 3 autres fichiers non. | Règle Step 4, 5, 7, 8, 9 : TOUS les fichiers de données (destinations.json, hotels.json, editorial.ts, cityContent.ts) doivent être triés alphabétiquement après toute insertion. Scripts de tri disponibles : /tmp/sort-citycontent.py et /tmp/sort-editorial.py. Pour destinations.json et hotels.json : \`python3 -c "import json;d=json.load(open('F'));d.sort(key=lambda x:x['slug']);json.dump(d,open('F','w'),indent=2,ensure_ascii=False)"\`. Vérifier après chaque Step que le fichier est trié. |
| 2026-04-22 | Daily run Nantes+Frankfurt : Nantes a passé toute la pipeline, mais Frankfurt a crashé au Step 4 avec \`API Error: Claude's response exceeded the 32000 output token maximum\` en essayant d'écrire \`data/city-guides/frankfurt.json\` en UN SEUL \`Write\` call. Le JSON city-guide complet (8 sections × 3 places × 3 langues + tips/faqs) dépasse les 32k tokens d'output. Nantes committée localement MAIS PAS PUSHÉE au moment du crash — perte partielle du travail si l'humain n'était pas intervenu. | (1) Step 4 : NE JAMAIS écrire un city-guide JSON complet en un seul \`Write\`. Procédure : écrire la coque (\`{"city":"...","guides":{}}\`) via Write, puis ajouter CHAQUE section (restaurants, parks, transport, beaches, vets, tips, attractions, petsitting) via un \`Edit\` séparé — 1 section par tool call. (2) Règle pipeline : \`git push origin main\` IMMÉDIATEMENT après le commit de la ville 1 (dans Step 12), AVANT d'attaquer la ville 2. Max 2 cities sequential = 2 commits + 2 pushes, pas 1 push final. Si la ville 2 crashe, la ville 1 est déjà live. |
