| 2026-04-21 | Prompt rendu avec fences \`\`\` imbriquées — le bloc externe terminait sur le premier \`\`\`bash interne, cassant l'affichage | Pour un prompt/doc à copier-coller contenant des exemples code, ne JAMAIS wrapper le tout dans un code fence externe. Utiliser du markdown plat avec blocs \`\`\`lang inline. |
| 2026-04-21 | Tâche Claude.ai cloud lancée sans setup initial → agent démarré dans /home/user vide (repo pas cloné automatiquement par le GitHub connector) | Toujours inclure en première section du prompt cloud : \`cd /home/user && git clone https://github.com/{owner}/{repo}.git && cd {repo}\`. Aussi configurer les secrets (GOOGLE_PLACES_API_KEY etc.) dans la config Claude.ai — le .env.local n'est pas dans le repo. |
| 2026-04-21 | Daily run Bilbao/Montpellier : apostrophes non-échappées dans une string single-quoted en TypeScript — \`'Puppy'\` dans \`'...'\` a cassé le build Vercel. Bizarrement la version EN/ES utilisait bien \`\\'Puppy\\'\` mais pas FR. | Dans les strings single-quoted de cityContent.ts, TOUTES les apostrophes/guillemets simples à l'intérieur doivent être échappés \`\\'\`. Alternative plus safe : utiliser des backticks \`\`\`...\`\`\` pour les strings contenant des citations. Ajouter \`npx tsc --noEmit\` dans Step 11 du pipeline AVANT le commit — l'audit ne détecte pas les erreurs TS. |
| 2026-04-21 | Même run : \`export default cityContent\` SUPPRIMÉ accidentellement quand l'agent a ajouté Bilbao/Montpellier en fin de fichier. Build Vercel crash "Export default doesn't exist". Mon \`npx tsc --noEmit\` sur UN seul fichier ne détectait pas ça (le fichier seul compile OK, c'est l'import depuis page.tsx qui échoue). | Ne JAMAIS éditer lib/cityContent.ts en insérant juste avant \`}\` final sans vérifier que \`export default cityContent\` est toujours en dessous. Step 11 du pipeline doit inclure \`npm run build\` COMPLET (pas juste tsc --noEmit sur un fichier), qui détecte les imports cassés. Alternative plus rapide : \`grep -c "^export default cityContent" lib/cityContent.ts\` doit retourner 1. |
| 2026-04-21 | Villes dans lib/cityContent.ts ajoutées par la tâche nocturne TOUJOURS en fin de fichier (Bilbao + Montpellier après Athens), désordre total (paris, barcelona, rome... puis chaos) | Les nouvelles villes doivent être insérées alphabétiquement. Règle dans Step 8 : trouver le slug qui vient APRÈS alphabétiquement et insérer JUSTE AVANT lui. Le fichier a été trié via scripts /tmp/sort-citycontent.py. Si ça repart dans le désordre, re-trier. |
| 2026-04-21 | Noms de sights avec descripteurs anglais collés : "Écusson Medieval Quarter", "Parc Méric Off-Leash Area", "Berges du Lez Riverside Walk" — le champ \`name\` n'est pas localisé, donc "Medieval Quarter" apparaît tel quel sur la page française. 11 noms cassés au total (Montpellier, Riga, Warsaw, Salzburg, Munich, Oslo, Tallinn, Bilbao). | (1) Le champ \`name\` des sights doit être un NOM PROPRE pur (locution dans la langue du pays ou neutre), jamais un descripteur anglais collé. (2) Si on veut ajouter une traduction, utiliser des parenthèses : "Stari Grad (Old Town Walls)" OK. (3) check-i18n.mjs a été étendu pour détecter automatiquement les descripteurs interdits (Off-Leash Area, Riverside Walk, Sculpture Park, Medieval Quarter, River Path, etc.) — tourne à chaque \`npm run build\` donc bloque le déploiement si présent. |
| 2026-04-21 | Link "← Destinations" sur page destination visible mais NON CLIQUABLE — l'image de fond du hero (\`<Image fill>\` dans un \`div.absolute.inset-0\`) couvre tout le hero et capture les clics. Le div de contenu n'avait pas de \`relative z-10\` donc restait sous l'image en stacking. | Règle pour tout hero avec image de fond \`absolute\` : (1) le div overlay image doit avoir \`pointer-events-none\`, (2) le div de contenu doit avoir \`relative z-10\` pour passer au-dessus. Vérifier systématiquement sur toute nouvelle page avec hero image que les liens/boutons sont réellement cliquables. |
| 2026-04-21 | Hôtels ajoutés par la tâche nocturne (et par les commits manuels) n'étaient étiquetés que \`dog-friendly\` et jamais \`cat-friendly\`, même quand la politique Booking dit "Pets are allowed" (ce qui inclut les chats). Résultat : les 9 villes récentes (Marseille, Rotterdam, Bologna, Cologne, San Sebastián, Toulouse, London, Bilbao, Montpellier) avaient 0 à 3 hôtels cat-friendly sur 5-6. | Règle Step 9 : si la politique de l'hôtel dit "Pets are allowed" (ou "dogs and cats", ou "animaux"), ajouter AUSSI \`cat-friendly\` dans \`categories\`. N'ajouter \`dog-friendly\` seul QUE si la politique exclut explicitement les chats ("only dogs", "dogs only"). La plupart des hôtels Booking pet-friendly acceptent les 2. |
| 2026-04-21 | L'agent nocturne a ajouté Bilbao + Montpellier À LA FIN de TOUS les fichiers concernés : destinations.json (ordre 50/51), editorial.ts (3 blocs en/fr/es), hotels.json. Résultat visible : pages catégories (dog-friendly, cat-friendly) affichent Bilbao et Montpellier hors ordre alpha. CityContent.ts avait déjà été re-trié, mais les 3 autres fichiers non. | Règle Step 4, 5, 7, 8, 9 : TOUS les fichiers de données (destinations.json, hotels.json, editorial.ts, cityContent.ts) doivent être triés alphabétiquement après toute insertion. Scripts de tri disponibles : /tmp/sort-citycontent.py et /tmp/sort-editorial.py. | 2026-04-22 | Daily run Nantes+Frankfurt : Nantes a passé toute la pipeline, mais Frankfurt a crashé au Step 4 avec \`API Error: Claude's response exceeded the 32000 output token maximum\` en essayant d'écrire \`data/city-guides/frankfurt.json\` en UN SEUL \`Write\` call. Le JSON city-guide complet (8 sections × 3 places × 3 langues + tips/faqs) dépasse les 32k tokens d'output. Nantes committée localement MAIS PAS PUSHÉE au moment du crash — perte partielle du travail si l'humain n'était pas intervenu. | (1) Step 4 : NE JAMAIS écrire un city-guide JSON complet en un seul \`Write\`. Procédure : écrire la coque (\`{"city":"...","guides":{}}\`) via Write, puis ajouter CHAQUE section (restaurants, parks, transport, beaches, vets, tips, attractions, petsitting) via un \`Edit\` séparé — 1 section par tool call. (2) Règle pipeline : \`git push origin main\` IMMÉDIATEMENT après le commit de la ville 1 (dans Step 12), AVANT d'attaquer la ville 2. Max 2 cities sequential = 2 commits + 2 pushes, pas 1 push final. Si la ville 2 crashe, la ville 1 est déjà live. |
| 2026-04-24 | Templates FR/ES injectent \`{cat}\` au milieu de phrases qui supposent un adjectif anglais ("Pourquoi {dest} pour des hôtels {cat} ?" → "Pourquoi Antwerp pour des hôtels Chiens acceptés ?" en FR). Les noms de catégories FR/ES ("Chiens acceptés", "Hôtels de luxe", "À proximité des parcs", "Sans supplément animaux") sont des locutions qui ne fonctionnent pas comme adjectifs avant "hôtels". En plus, \`dest.name\` (toujours en anglais dans destinations.json) est utilisé tel quel dans les meta titles/descriptions FR/ES → "Antwerp" au lieu de "Anvers", "Belgium" au lieu de "Belgique". | (1) Templates avec \`{cat}\` dans dictionaries/{fr,es,en}.json : utiliser un séparateur (— ou :) au lieu d'imbriquer la catégorie comme adjectif. Ex : \`Hôtels à {dest} — {cat}\` au lieu de \`Meilleurs hôtels {cat} à {dest}\`. Pour le \`whyTitle\` : drop le \`{cat}\` complètement, mettre \`Pourquoi choisir {dest} avec votre animal ?\` (la catégorie est déjà dans les bullets). (2) Toujours utiliser \`getLocalizedCityName(slug, name, locale)\` pour le nom de ville et \`getLocalizedCountryName(country, locale)\` pour le pays dans tout texte FR/ES rendu (titles, meta descriptions, body). Les schémas JSON-LD et alt-text peuvent rester en anglais. (3) Avant de commit un template avec \`{var}\`, simuler le rendu avec les 6 catégories réelles (Chiens acceptés, Chats acceptés, À proximité des parcs, Hôtels de luxe, Accès à la plage, Sans supplément animaux) — si une variante produit une duplication ("hôtels Hôtels") ou une formule cassée, retravailler. |
| 2026-04-24 | Section \`petsitting\` avait 22+ cartes avec des photos absurdes : Google Places matchait "Rover Strasbourg/Naples/..." sur les concessionnaires **Land Rover** locaux → une concession automobile s'affichait à la place d'une plateforme de pet-sitting. Pawshake/Holidog même problème (entreprises différentes au même nom). Aussi : "Berges de l'Ill en Petite France" (Strasbourg) → Google Places n'a rien trouvé (zone diffuse, pas un POI précis) → photo manquante visible sur le front. | (1) Ne JAMAIS fetcher Google Places photos pour la section \`petsitting\` — ce sont des plateformes en ligne (Pawshake, Rover, Holidog) sans lieu physique. Le script \`fetch-city-guide-photos.mjs\` skip désormais cette section entièrement (le front gère \`!place.photo\` avec un header sans image). (2) Pour les zones diffuses (berges, promenades, quartiers non-POI), ajouter dans la prochaine itération un fallback : si \`No photo found\`, retry avec une requête ciblée sur un POI précis de la zone (ex: "Berges de l'Ill" → "Ponts Couverts Strasbourg"). Pour l'instant, fix manuel si détecté. |
| 2026-04-26 | "PLUS DE DESTINATIONS EN SPAIN" et plein de fuites d'anglais sur le site (countries/page.tsx, OG images, DestinationsGrid, TopHotels, generateXXX dans editorial.ts). Aussi, tentative de remplacer **dog-friendly** par "accueillant les chiens" en FR a cassé la grammaire dans les superlatifs ("les villes les plus accueillant les chiens" — faux, faut "accueillantes pour"). En ES, "que admiten perros" cassait les relatives ("la capital que admiten perros de Europa"). | (1) **Audit i18n parallèle** : lancer 3 agents Explore en parallèle pour scanner (a) static text leaks, (b) content data files JSON/TS, (c) dictionaries + components. Plus rapide qu'un seul agent et ratisse plus large. Inclus les composants \`components/home/*\` et les fichiers \`opengraph-image.tsx\`. (3) **Anglicismes acceptés** : \`dog-friendly\` et \`pet-friendly\` ne se traduisent PAS — leur remplacement littéral casse la grammaire FR/ES. \`off-leash\` → \`sans laisse\` / \`sin correa\` et \`on-leash\` → \`en laisse\` / \`con correa\` SE traduisent (compléments propres, pas adjectifs). (4) **Avant tout sed/regex bulk-replace** sur du contenu, tester sur 5-10 occurrences à la main avec différents contextes grammaticaux (comparatif, superlatif, attribut, complément) — si UNE produit du charabia, abandonner et garder l'anglicisme. |
